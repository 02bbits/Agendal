# Docs changelog

What changed in the docs, newest first. Each entry names the files and IDs touched; the full text is in git history.

## 2026-11-02

- **Composable note modifiers.** Relative durations, repeat intervals/counts and comma boundaries share quantity grammar. Scheduling-only fragments bind to their task, and leading dates preserve shopping lists. Unresolved quantities, exclusions and conflicting relative timestamps keep their full constraints for fallback. [NU](03-modules/NU-note-understanding.md#relative-time) and [70 complex HTTP cases](../backend/tests/Manual/complex-note-cases.md) describe the behavior.

- **Calendar shorthand and manual checks.** Monthly dates accept ordinal numbers without `the`; weekday ordinals can share one weekday (`first and third Monday`). Unresolved repeat words stay low confidence. [67 manual HTTP cases](../backend/tests/Manual/note-cases.md) include title cleanup and the existing NU-E6 rule for multiple dates.

- **Calendar list parsing and repeated copies.** The splitter preserves weekday/month-date lists and literal commas before finding task boundaries. Notes can create numbered daily series from an explicit per-day count, separately from the series-end count. Vietnamese weekday introducers leave no stray title text. Unsupported time allocations preserve the full request. See [NU extraction](03-modules/NU-note-understanding.md#25-extraction-nu-2) and the [API contract](07-architecture/api.md#notes-with-multiple-tasks-per-scheduled-day).

- **Calendar recurrence contract (IM-37, #117).** [API](07-architecture/api.md#task-recurrence-contract-im-37), [TK §7–8](03-modules/TK-tasks.md#7-api-contract) and [NU §2.5/7](03-modules/NU-note-understanding.md#25-extraction-nu-2) distinguish the frequency `repeat`, nullable RRULE `repeat_rule` and server-maintained `repeat_anchor`. The [data model](07-architecture/data-model.md), [task schema](07-architecture/contracts/schemas/task.schema.json), [note-result schema](07-architecture/contracts/schemas/note-result.schema.json) and task fixtures follow. The API reference owns validation limits, PATCH clearing rules and compatibility details; NU keeps note-recognition examples.
- **Frontend presentation (#117).** Shared `describeRepeat(task, locale)` formats structured recurrence data into English/Vietnamese text for task details and accessible names. Backend scheduling remains authoritative.
- **Completion and Undo (#117).** The API documents the different meanings of `next` in complete/reopen responses, idempotent retries and recompletion. Calendar rules skip missing dates; legacy enum-only tasks retain month-end clamping.

## 2026-11-01

- **Moves that change nothing (IM-35).** [NU §2.4](03-modules/NU-note-understanding.md#24-command-matching-nu-3): a move to the date and time the task already has is skipped with the new reason `no_change`; [NU §2.6](03-modules/NU-note-understanding.md#26-safety-and-status-nu-5-br-01-br-02) counts it like `already_done` and `not_found`. The [note-result schema](07-architecture/contracts/schemas/note-result.schema.json), NU §7 enums, the [note corpus](06-testing/note-corpus/README.md) format, [RV](03-modules/RV-review-control.md) and the [copy catalog](01-product/copy-catalog.md) add `no_change` and `note.skip_no_change`.
- **Result screen (IM-43).** [RV §2.1](03-modules/RV-review-control.md#21-result-screen-rv-1): the meta of a row is the server's `label` plus "was …" for an update, the screen has **Done** only until Undo all ([IM-44](08-project/tasks.md#im-44)) and Edit note ([IM-47](08-project/tasks.md#im-47)) land, and each task is read by id so a removed one shows "Removed since". Pending copy keys `note.result_hint`, `note.show_all` and `note.show_less`.
- **Three inconsistencies settled (#102).** (1) A note with nothing actionable gets the follow-up everywhere, with two options: **Keep it as task** (the whole text becomes one task titled with it) and **Edit the note** (opens the editor, same as Edit note). **Keep as note** is gone, so a follow-up note the user doesn't act on stays `followup` and shows as needing a look. [BR-02](02-domain/business-rules.md#br-02), the note-naming table, [RV-3](03-modules/RV-review-control.md#rv-3) and [RV §2.3](03-modules/RV-review-control.md#23-follow-up-rv-3), [WF-03](04-workflows/WF-03-resolve-unclear-note.md), the [domain](02-domain/domain.md) state machine and diagram, [TS-06](06-testing/test-scenarios.md#ts-06) and IM-46 follow. The `kept` status now comes only from Cancel in Check this first. [API](07-architecture/api.md): `POST /notes/{id}/keep` is removed (`make-task` is Keep it as task; Edit the note uses `PUT /notes/{id}`). [Copy catalog](01-product/copy-catalog.md): `note.keep` is retired, `note.followup_edit` ("Edit the note") is added and `note.make_one` now reads "Keep it as task". T-RV-21 is retired; T-RV-23 covers Edit the note. (2) "Check this first" now starts at **5 or more** changes in one note, not more than 5 (a task counts once however many fields change): [BR-01](02-domain/business-rules.md#br-01) is rewritten, and [NU-5](03-modules/NU-note-understanding.md#nu-5), NU §2.6, [WF-01](04-workflows/WF-01-capture-and-process-note.md), [WF-02](04-workflows/WF-02-confirm-risky-changes.md), the [domain](02-domain/domain.md) diagrams, the [overview](01-product/overview.md), [TS-05](06-testing/test-scenarios.md#ts-05) and the T-NU-41 boundary (4 → `done`, 5 → `confirm`) follow; [Q5](08-project/open-questions.md#q5) is amended. Code and tests follow in #103. (3) The tablet and desktop layout is in v1: [NF-8](05-quality/nfr.md#nf-8) now lists the three layouts, the [overview](01-product/overview.md) drops "desktop layout" from Later and rewords the non-goal, and the [project](08-project/project.md) constraint says responsive from 320px up.
- **Graphite design (V2.1, #97).** [Theme guide](01-product/theme-guide.md) is rewritten for Graphite (monochrome greys, Inter) and replaces Paper & ink; the reference package is not in git and is linked from the guide. [Screens](01-product/screens.md): no serif, "Made from your note" link, round + button. [Overview](01-product/overview.md) and [project](08-project/project.md) name Graphite. [Tasks](08-project/tasks.md) IM-06 maps the Graphite tokens. The UI rework is #98; the `task.created_by_assistant` string changes with it.
- **Note editor layout (#98).** [NC §2.1](03-modules/NC-note-capture.md#21-editor-nc-1-nc-2-nc-5): the editor follows the Graphite New note screen: Cancel and "✦ New note" bar, "Your note" card, helper line, "Try writing" examples, full-width Make tasks. Cancel replaces ×.
- **Submitting a note (IM-42).** [NC §2.2](03-modules/NC-note-capture.md#22-submit): the editor sends `POST /notes` and, until the result screen ([IM-43](08-project/tasks.md#im-43)) and the offline queue ([IM-53](08-project/tasks.md#im-53)) exist, a success closes the editor with the `note.made_*` toast and a failed send keeps the text with Retry. A new `client_id` is made when the text changes after a failed send. New copy key `note.send_failed` ("Couldn't send your note. Check your connection and try again."), pending in the front end until it joins the [copy catalog](01-product/copy-catalog.md); IM-53 goes back to `note.processing_failed`.
